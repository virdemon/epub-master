# EPUB Master — EPUB 排版与压缩大师

把一本排版失控的 EPUB 处理成「手机、墨水屏、平板、电脑上看起来一样」的版本，
体积压到你能接受的上限以内，装不下就按章节拆成多卷。

纯本地工具：文件在你的电脑里解包、重排、打包，不联网、不上传。

```
┌─────────┬────────────────────────────┬──────────────┐
│ 首页    │  拖入 EPUB / 书籍卡         │ 处理模式     │
│ 批量处理│  预览原书 / 参数 / 进度     │ 输出目标     │
│ 历史记录│  结果分析 / 输出文件        │ 处理选项     │
│ 工具箱  │                            │ [开始处理]   │
│ 设置    │                            │              │
│ 关于    │                            │              │
└─────────┴────────────────────────────┴──────────────┘
```

首页只做一条线：拖入 → 看到这本书 → 预览原书 → 定参数 → 处理 → 看结果。
以前首页底部那排快捷工具（图片优化/SVG/表格/元数据/修复/批量）已经删掉，
它们都在「工具箱」里，首页不再重复一遍。

## 第五轮：排版兼容性专项（v2.3）

### 先定位真实原因，不是先说"加条缩进"

用真实书（`成为令强者们痴迷的装备制作师.epub`，158 章、40 图、OPF `version="1.0"`）跑了一遍引擎，问题在**结构**，不在 CSS：

| 现象 | 真实原因 | 位置 |
| --- | --- | --- |
| 处理后正文糊成一大块（截图三） | `tidyChildren()` 里的"连续 `<br>` 计数"只增不减：文字节点被 `continue` 跳过，没有把 `brRun` 归零。整章出现过 3 个 `<br>` 之后，后面每一个 `<br>` 都被判成"多余换行"删掉，实测量级 **68475 个** | `core.js` `tidyChildren` |
| 首行缩进全丢（截图一） | 这本书正文是 `<h1>…</h1>` + 一整块文字 + `<br>`，**一个 `<p>` 都没有**。`rebuildParagraphs()` 只要发现这一层有块级子元素（h1）就直接 `return`，于是整章一段都没重建，缩进没有地方挂 | `core.js` `rebuildParagraphs` |

结论：任何"再加一条 `p{text-indent:2em}`"的做法都救不了这两个问题——没有 `<p>`，也没有换行。

### 改了什么

| # | 改动 | 说明 |
| --- | --- | --- |
| 1 | 修 `tidyChildren` 的换行计数 | 文字节点也参与计数，只有**真正连续**的 3 个以上 `<br>` 才裁；`removedExtraBreaks` 从 68475 降到 0 |
| 2 | 重写 `rebuildParagraphs` | 不再因为同层有 `<h1>`/`<img>` 就整体放弃；按块级元素把内容分组，每组再按 `<br>` 切段。实测这本书重建出 **42991 个** `<p>` |
| 3 | 硬折行合回同一段 | 上一行没有句末标点（`。！？!?…` 等）时，把下一行接回同一段，避免"一句完整的话被切成两段碎行"。实测合并 **2958 处** |
| 4 | `splitBrParagraph`：整章塞在一个 `<p>` 里 | `<br>` ≥ 2 的段落按句拆成多个 `<p>`，第一段继承原 `id`/`class`；修了拆完兄弟节点被"整层重建"清掉的隐患 |
| 5 | 空行里的图不能当空格扔掉 | `hasKeepable()` 原来只查 `getElementsByTagName('img')`（查不到节点自己），整本书 39 张插图被当成空行删掉；现在图片、锚点都保留 |
| 6 | 特殊内容一律不进正文段落 | `<table>` `<figure>` `<pre>` `<ul>` `<blockquote>` `h1-h6`、`li/td/pre` 内部、`class="poetry/poem/verse/poem"` 全部原样保留；图片单独成 `<p class="ef-img">`，居中、不缩进 |
| 7 | 新段落带 `class="ef-p"` | 样式层只认这个类。**"保留原始样式表"模式也不会动到原书本来就规整的段落**，只给"修出来的段落"补缩进 |
| 8 | 两套样式表口径统一 | `full`（替换原 CSS）与 `safety`（保留原 CSS）共用同一组数值：2em 缩进、0.6em 段距、1.75 行高、标题居中无缩进、图片/表格/列表/引用/诗歌排除在外。2.0 与 3.0 拿到的是**同一个文件**，不会再出现一个版本正常、一个版本糊掉 |
| 9 | 结果页新增「排版兼容性检查」 | 11 项全部由输出包里的真实 XHTML/CSS 算出：段落结构、正文完整性（比对原书字数）、段落来源、样式表引用、缩进与段距、章节标题、特殊内容保护、图片资源、重新解析、版本结构、兼容性风险。状态分「已修复 / 检查通过 / 需要确认 / 风险提示」，打包成功不会显示成"排版全部正常" |
| 10 | 阅读窗口加「对照」按钮 | 原书 ⇄ 处理结果一键切换，停在同一章（按章节名匹配），不用重新找位置 |

### 已知限制

- 硬折行合并只能按"上一行有没有句末标点"判断。作者本来就写成一行的句子（如 `材料？`）仍然是独立段落——这是原书的结构，不去猜。
- `诗歌/poem/verse` 这类 class 才认得出诗歌块；没有 class、只用 `<br>` 排的诗，会被当成若干短段落处理。
- 标准优化（保留原书样式表）下，原书 `p{text-indent:0}` 仍然生效——报表里会写明"个别段落的缩进以原书为准"，想统一请用深度优化。
- 无法自动化验证微信读书等第三方阅读器的实际显示，只能保证结构与样式简单、可预期（本仓库的校验覆盖到"输出能被重新解析 + 无失效引用 + 无绝对单位"）。

## 目标体积：先压图片，压不下去才分卷

**分卷默认是关闭的**，默认永远输出一个完整 EPUB。分卷开关收在「高级设置 → 分卷」里，
关着的时候"切分方式""目标体积"两组选项整个不显示，右侧面板也同步显示"分卷：关闭"——
不给人"是不是已经在拆了"的错觉。

打开之后才选切分方式（一级标题 / 二级标题）与目标体积（自动 / 20 / 50 / 100 MB / 不限）。
选 20 / 50 / 100 MB 时，这个数字身兼两职：

1. 先当**压缩上限**——按「目标 − 文本体积」算出图片预算，逐张分配，把图压进预算
2. 还压不下去（文本本身太大）→ 再当**分卷上限**，按章节边界切成多卷

每一卷都是完整、独立、能单独打开的 EPUB：各自的 `nav.xhtml`、`toc.ncx`、OPF，只带自己需要的那几张图。

实测：24 章纯文本书按 8 KB 上限处理 → 12 卷，每卷 2 章，章节合计 24 章、逐章比对与原书顺序完全一致、
无重复无遗漏，12 卷各自跑 23 项结构校验全部通过，每卷有独立的 `dc:identifier`。
单章本身超过上限时不会截断章节，而是让那一卷大一点，并在结果里写明原因。

## 结果页：两种体积口径分开写，谁也不许冒充谁

处理完这一页要回答四个问题：小了多少、小在哪、有没有白忙、文件在哪。所以它由四段组成：

1. **概览**：原始体积 / 处理后体积 / 节省空间 / 体积减少比例 / 耗时 / 处理模式 / 输出文件数。
   比例的定义直接写在数字下面：`（原始 − 处理后）÷ 原始`。变大了就如实显示负数，不藏
2. **资源分析**：图片 / 文本 / 字体 / 其他，每类给出发现数量、实际做了哪些操作、
   处理前后各多少字节、省了多少。没有可优化内容的类别会明说"保留原样"并解释为什么，
   而不是画一根空进度条糊过去
3. **输出文件**：单卷显示一行，多卷逐卷列出行、章数、体积，点一行可直接预览那一卷
4. **操作**：保存到输出目录 / 预览处理后的书 / 预览原书 / 打开输出目录 / 处理日志 / 继续处理下一本

**两套口径必须分清，这是上一版最刺眼的自相矛盾：**

| 口径 | 字段 | 含义 | 能不能相加 |
| --- | --- | --- | --- |
| ZIP 文件大小 | `inputBytes` / `outputBytes` | 磁盘上那个 `.epub` 本身多大（压缩后） | 只能和 ZIP 比 |
| 解压后资源大小 | `rawTotal` / `afterRawTotal` | 解开后各类文件字节数之和 | 只能和同类资源比 |

界面上把它们放在两处，中间写着"下面的体积是解压后的资源大小，和上面的 ZIP 文件体积口径不同，
不能直接相加"。分类面板里"处理后"的数字是**按真正写进 ZIP 的条目**累加出来的，
不是拿中间产物估的——否则会出现"图片 1.71 MB，而整个 EPUB 只有 1021 KB"这种鬼话。

## 默认输出目录

`下载\EPUB_Master`，用系统给的下载目录拼出来（`app.getPath('downloads')`），不写死用户名、不假设盘符，
不存在就建。可以在设置里改成别处，改过会记住，随时能"恢复默认"。

- 绝不覆盖原始 EPUB：输出目录和源文件目录本来就是两处
- 同名不覆盖：`书名.epub` 已存在就写 `书名 (2).epub`
- 写入失败会明确报错（哪个路径、什么原因），不会静默改成别的地方，也不会假装保存成功

## 结构诊断与修复（"此文件未列在manifest文件中"的解药）

从网站下载、工具转换来的书，最常见的坏法是**图片在包里、manifest 里一张都没声明**。
阅读器会逐张报「此文件未列在manifest文件中」，表现就是插图全空。

这里的 manifest 不是照抄原书，而是**由输出包里真实存在的文件生成**，所以两个方向的错都修：

- 包里有、manifest 没声明 → 补上，并纳入压缩
- manifest 声明了、包里没这个文件 → 从新 manifest 移除
- `<meta name="cover">` 指向已丢弃的条目 → 移除
- 引用路径大小写写错、被 URL 编码 → 先解码再按真实文件名匹配
- 引用了一张不存在的图 → 删掉死引用并清理空父容器
- 元数据里 calibre / Sigil 的残留、重复的 `dcterms:modified`、重复的书名 → 清掉

工具箱里的「结构检查」会先列出问题再让你决定修不修，不点就不动文件。

## 排版：向阅读器里那种 TXT 看齐

- 首行缩进 2em，全部相对单位
- **每段一个 `<div>` 的书会降级成 `<p>`**。网页抓来的小说普遍这么写，而缩进规则只挂在 `p` 上——这是"改完还是顶格"的主因
- **按 `<br>` 分段不再被同层 `<p>` 挡住**：原来"整层有 `<p>` 就跳过"的判断，会让一个图注 `<p>` 毁掉全章缩进
- 空段落、空容器、连续空行清掉
- 加粗/斜体显式声明 `font-weight` / `font-style`，避免被阅读器默认值盖掉
- 插图去掉写死宽高、独占一行居中、保持原文顺序
- 标题识别退化顺序 `h1 → h2 → h3`，网页书常用二级标题当章名

## 预览：一个是"原书长什么样"，一个是"处理后长什么样"

预览是一个**独立的阅读窗口**（全屏覆盖，不是嵌在卡片里的一小块），布局固定为：

```
┌ 书名 · 作者 · 章数 · 图片来源                       原书样式 | 阅读样式 | × ┐
├──────────────┬───────────────────────────────────────────────────────────┤
│ 目录 5 项    │ 第一章　渡口无船                          第 2 / 5 章        │
│  版权页      │                                                           │
│  第一章 ◀    │   　　正文……（可拖动中间的竖线调目录宽度）                │
│  第二章      │   [插图按原样出现在它本来该在的位置]                      │
│  第三章      │                                                           │
│（目录自己滚动）│                                                           │
├──────────────┴───────────────────────────────────────────────────────────┤
│ [上一章] [下一章]                        A− A+ │ − 100% + 重置           │
└──────────────────────────────────────────────────────────────────────────┘
```

- **左侧目录固定宽度**（默认 264 px，高分屏 280 px），可拖分隔线在 180 px–55% 之间调整，
  目录再长也只在自己那一栏里滚动，不会把正文挤成一条缝
- 目录项和章节名一律 `nowrap + ellipsis`，悬停有 `title` 显示完整标题——短标题不换行，长标题不撑破
- 正文渲染在 `iframe.srcdoc` 里，**原书的 CSS 与软件界面彻底隔离**；原书样式表会被真正注入，
  图片、SVG、表格、行距、字体、图文混排都按原结构呈现，不是把文字抽出来拼成纯文本
- 图片按需转 `data:` URL（打开第几章才转第几章），所以 90 MB 的书也能秒开第一章；
  超长图点击可全屏查看
- 两种模式：「原书样式」看这本书本来的样子，「阅读样式」套一层统一排版（首行缩进 2em、
  行距 1.75、图片居中），用来快速判断"改成 TXT 那样好不好读"。原书样式下字号由书决定，只能缩放
- 只读：不改源文件、不生成临时 EPUB；关闭时释放章节缓存，之后再读会明确报"预览已关闭，请重新打开书籍"

入口有两个：书籍卡上的「预览原书」（导入后立刻能看，不用先处理）、结果页的
「预览处理后的书」（看的就是输出包里那份真实结果，可分卷选卷）与「预览原书」（前后对比）。

### 图片浏览（与原书阅读并存）

阅读窗口顶部第二个标签就是它，切换不重开书、不重新解包。

- 网格按窗口宽度自适应列数，缩略图统一 132px 高的方格 + `object-fit: contain`：
  比例不变、不裁切、长宽比不同的图也不会把网格撑歪
  （**踩坑**：`aspect-ratio` 放在 grid 项的 flex 列里算不出高度，整行会塌成 38px，
  卡片高度也跟着塌；改成固定行高 + 固定缩略图高度才稳定）
- 缩略图按需：滚到视口附近（`rootMargin: 420px`）才解码，`createImageBitmap` 缩到 320px
  画进 canvas，随即 `bm.close()`；位图不留在内存里，只留一条 dataURL
- 原图按 LRU 只保留最近 4 张 objectURL，翻走的立即 `revokeObjectURL`；退出阅读窗口全清
- 每张卡片写：文件名、像素、体积、格式、出现在第几章（只在 CSS 里出现的写"样式表引用"，
  哪都没有的写"未在任何章节中出现"并打「未引用」标）
- 工具栏：搜索文件名、按引用顺序/大小/分辨率/文件名排序、按长边（800/1200/2000）或体积（500KB）筛选、
  只看正文引用；筛空时给明确文案，不留白屏
- 大图：适应窗口（`max-width` + `max-height` 双向约束，竖长图也放得下）/ 原始尺寸 / ±20% 缩放 /
  上一张下一张 / 键盘 ←→ / Esc（只关大图层，不关阅读窗口）
- 解码失败（例如 HEIC）就在缩略图上写"XX 无法在当前环境解码"，不会让整页崩

**对比原图**只在「从结果页打开」时可用。匹配顺序是：完整路径 → 去掉扩展名的文件名
（压缩会把 `p1.png` 转成 `p1.jpg`，只按路径比永远对不上）。匹配成功会写明是按哪种方式对上的，
两边各自标注体积与像素；同名多张或完全对不上时明确提示"无法确认是同一张"。

## 输出格式：EPUB 2.0 / 3.0

「保留原书版本」是默认项，也是推荐项；另外两项会**按目标版本重建包结构**，不是改版本号：

| | EPUB 2.0 | EPUB 3.0 |
| --- | --- | --- |
| OPF `version` | `2.0` | `3.0` |
| 目录 | NCX 必备，`spine` 带 `toc` 指向它 | `nav.xhtml`（`properties="nav"`）+ 保留 NCX 兼容老阅读器 |
| manifest | 不能有 `properties` | 允许，`cover-image` 声明封面 |
| 章节文档 | XHTML 1.1 DOCTYPE、`http-equiv="Content-Type"`、不声明 `xmlns:epub` | HTML5 DOCTYPE、`<meta charset>` |
| 元数据 | 无 `<meta property>`，用 `dc:date` | 必须有 `dcterms:modified` |
| 正文 `epub:*` 属性 | 全部剥掉 | 原样保留 |

写完立刻自检（`verifyVersion()`）：OPF 声明、manifest 每个文件是否真实存在、2.0 是否残留
nav/properties/`epub:` 前缀、3.0 是否有 nav 与 `dcterms:modified`。结果页「输出版本」框显示
版本、自检结论、文件数与体积；装不下的特性（内联 SVG、SVG 文件、HTML5 语义标签、
video/audio/canvas、MathML）逐条列出"原样保留但老阅读器可能不显示"，不静默丢弃。

独立校验脚本 `tools/check_version.py` 用 Python 重新解包核对同一批断言，
7 种组合（2.0 原书 / 3.0 原书 × 保留 / 强制 2.0 / 强制 3.0，外加带封面的真书）
全部通过，`verify_epub.py` 一并通过。

| --- | --- | --- | --- | --- |
| 图文混排（10 章 / 4 图 / 2.6 万字） | 18.69 MB | 不限 | 2.72 MB | 省 85.4%，`verify_epub.py` 23 项通过 |

## 第六轮：智能重复图片清理（v2.4）

### 判定规则（只认"确定相同"，不确定的一律保留）

| 层次 | 方法 | 说明 |
| --- | --- | --- |
| 第一层 | 文件字节的 SHA-256 | 哈希相同就是同一个文件，文件名、目录、扩展名不同也认 |
| 第二层 | 解码后逐像素比对 | 只对"同尺寸 + 体积差 ≤5%"的候选对，像素数组完全一致才算重复 |

明确**不做**的事：不看文件名是否相似、不比尺寸或体积是否接近、不算感知哈希、不做相似度评分。
画面相近但像素有差异的图，一律当两张不同的图。像素比对有两轮（先比字节数完全相同的，
再比体积差 5% 以内的相邻图），总预算 60 对，用完即停，并在检查项里注明。

### 删的是"显示位置"，不是资源文件

按 spine 阅读顺序逐章扫 `<img>`（含内联 SVG 里的 `<image>`），第一次出现的位置保留，
之后的重复位置只删这一处引用。资源文件是否从输出包里去掉，由打包阶段按
"还有没有人引用"决定：还被第一章引用的图一个都不会删。

### 三道统计口径，绝不混用

| 指标 | 含义 |
| --- | --- |
| 正文图片位置 | 正文里扫到的 `<img>` 个数 |
| 不同图片 | 内容互不相同的种类数（= 保留的首次出现位置数） |
| 清除重复显示 | 被移除的重复位置数 |
| 移除冗余资源 | 内容相同、且已无人引用的文件个数（真正的文件减少量） |
| 实际节省 | 上述冗余文件解压后的字节数 |

结果页「重复图片清理」区块展示这五个数字，并可展开逐张清单：
文件名、体积、判定方式（内容哈希 / 像素比对）、保留在第几章、清除了哪些位置
（同章内的重复标注"同章重复"）。

### 新增的输出完整性检查

`runTypographyAudit()` 从 11 项扩到 14 项，新增：

- **重复图片**：清了几处位置、删了几个资源文件、有几组靠像素比对确认、有几处认不出而保留
- **目录与章节**：逐章核对 NCX（以及 3.0 的 nav）里是否真能点到，不是"生成了目录所以一定对"
- **输出完整性**：每个输出包重新解析后核对 mimetype 首条未压缩、container 指向正确 OPF、
  manifest 每个条目都真实存在、spine 每个 idref 都能对上

### 原始文件永远不动

`process()` 只读输入字节（测试里逐字节比对过处理前后的输入数组），所有改动都发生在
解包后的内存副本上，输出写进新的 ZIP。没有备份、没有临时目录、没有原地写回。

### 实测

| 书 | 位图 | 显示位置 | 清除 | 冗余资源 | 耗时 |
| --- | --- | --- | --- | --- | --- |
| 真实书（70.6 万字 / 40 图） | 40 | 40 | 1 处 | 1 个（38 KB） | 3.7 s |
| 重复图片样书（94 章 / 96 资源） | 96 | 280 | 186 处 | 2 个（21 KB，压缩后） | 1.1 s |
| 图文混排（10 章 / 4 图） | 4 | 3 | 1 处 | 1 个（1014 KB） | 0.4 s |

## 第七轮：排版回归修复（v2.5）

### 真正的成因（不是排版代码被删了）

`rebuildParagraphs` / `segmentParagraphs` / `buildCss` 一行都没丢，第五轮的段落重建、
2em 缩进、硬折行合并全部还在。问题出在**样式层选错了**，两个具体缺陷：

1. **`safety` 版本只给 `p.ef-p` 缩进。** "标准优化"模式保留原书样式表，这时只用
   safety 层 —— 原书有 CSS 时没问题；但输入若是**上一轮处理过的书**（包里只剩我们
   自己写的 `epubfix.css`）或原书根本没有样式表，就变成"只有重建出来的段落有缩进，
   其余段落和所有标题完全没样式"，看着就像排版功能没了。
2. **同名样式表被声明两次。** 二次处理时 `keepCssFiles` 里已经有一份
   `OEBPS/epubfix.css`，拼上我们新写的那份后，manifest 出现两条同 href 的 item
   （ef3 / ef4），每章 head 里也链两遍。

### 修法

| 改动 | 说明 |
| --- | --- |
| safety 层加正文兜底 | `p { text-indent:2em; margin:0 0 .6em; line-height:1.75 }`、`h1–h6 { 居中; text-indent:0 }`。都是**类型选择器**（最低优先级），原书 `.calibreN` 之类一定盖得住，只做垫底 |
| 特殊内容保护 | `blockquote p / li p / td p / .poetry p / .center / .noindent …` 优先级更高，照旧不缩进 |
| 样式层自动降级 | `preserveCss` 但一份原书样式表都没留下时，改用完整样式层（`full`），理由是没有"原设计"可保，只有兜底层会让整本看着没排过版 |
| 样式表引用去重 | `keepCssFiles` 里剔掉与 `cssPath` 同路径的项；`buildOpf` 再按 href 去重一次 |
| 报告新增 | `report.cssKind`（实际用的是 safety 还是 full）、`report.keptCssFiles`（保留了哪几份原样式表） |

### 四种组合实测（真实书 155 章 / 70 万字，2.0 源）

| 模式 | 输出 | 首行缩进 | 段距 | 行高 | 标题 | 样式表 |
| --- | --- | --- | --- | --- | --- | --- |
| 标准 | 2.0 | 32px = 2em | 有 | 1.75 | 居中 0 缩进 | 原 2 份 + epubfix |
| 标准 | 3.0 | 32px = 2em | 有 | 1.75 | 居中 0 缩进 | 原 2 份 + epubfix |
| 深度 | 2.0 | 32px = 2em | 9.6px | 1.75 | 居中 0 缩进 | epubfix |
| 深度 | 3.0 | 32px = 2em | 9.6px | 1.75 | 居中 0 缩进 | epubfix |

上表数字不是"配置里写了 2em"，是把输出包解开、用浏览器真渲染一章后量出来的
（`node test/style_regress.js <书>`）。同设置下 2.0 与 3.0 的缩进逐像素一致。

- **图片优化**：列出每张位图的尺寸与体积，只压图片、不动正文

- **封面提取**：把封面原图导出成独立图片，EPUB 一个字节都不动

## 批量与历史

- 批量队列可混选模式，并发 1–3，**单本失败不影响其他任务**（失败项标红并给出原因，可重试）
- 历史记录只存在本机 localStorage，最近 100 条，可一键清空

## 两个技术决定，值得单独说

**自己写 ZIP 打包器。** fflate 的 deflate 在中文长文本上比系统 zlib 差 5%，且 level 9 与 level 6 输出完全相同——文本多的书会出现"压完反而变大"。改用浏览器原生 `CompressionStream('deflate-raw')` 预压缩，再手写 ZIP 头（本地头 / 中央目录 / EOCD / 自实现 CRC32）。同一样本从 399,893 字节降到 382,278 字节。

**不用 `XMLSerializer` 输出 XHTML。** HTML DOM 经它序列化会得到 `<br>` 而非 `<br/>`，那不是良构 XML，部分阅读器直接白屏。改为自写序列化器，固定输出自闭合标签。

## 已知限制

- **不支持 DRM 加密书**，解包即失败，设计如此
- **超过 300 MB 会在界面警告**：解包后图片占用内存是原文件数倍，浏览器有可能崩，这个量级建议用桌面版
- **章节切分依赖 `h1`–`h6`**：原书用 `<p class="title">` 标章节时切分不生效，工具会明说而不是假装处理过
- **纯文本书压缩空间很小**，1%–5% 就是极限
- **预览不做分页**，是连续滚动；页码只有一个"第 n / m 章"的位置指示
- **预览的"原书样式"仍可能被安全网样式轻微影响**（`img{max-width:100%}`、防溢出），
  只为避免图片撑破窗口，不改变字号与行距
- **单个 EPUB 内部若有多份互相冲突的 CSS**，阅读器之间本来就不一致，这里按原书顺序注入，不做仲裁
- **桌面版 exe 本身仍是 Electron 默认图标**，窗口与任务栏图标已经换成自己的（改 exe 图标需要 rcedit，当前环境拿不到）
- **没有更新服务器**：关于页的"检查更新"会如实说明这一点，不假装检查成功
- **图片浏览能显示什么，取决于浏览器解得了什么**：PNG / JPEG / GIF / WebP / BMP / SVG 都能显示，
  HEIC、AVIF 这类当前内核解不了的会在缩略图上直接写"无法在当前环境解码"，不会留下白框，也不会崩
- **图片浏览是只读的**：不改原包、不生成临时文件；它只回答"这本书里到底有哪些图、多大、在哪一章"
- **没被任何章节或样式表引用的图片，输出时不会写进新包**（它们是死资源）。结果页会写明有多少张、
  占多少 MB、为什么跳过——不会静默减少。想先确认这些图真没用，用图片浏览的「未引用」标筛一遍
- **EPUB 2.0 装不下的东西不会强改**：内联 SVG、SVG 文件、HTML5 语义标签、MathML、video/audio
  在转 2.0 时原样保留并在结果页逐条警告——把它们改成 `div` 会连 CSS 选择器一起失效、排版直接散架，
  那比"校验器报一个未知元素"更糟
- **`dcterms:modified` 用当前时间**：每次输出都会刷新，这是 3.0 的规范要求，不是原书元数据缺失

## 文件结构

```
epubfix/                网页版（也是唯一一份源码）
  index.html            三栏界面 + 独立阅读窗口 + 关于页
  style.css             设计 token + 布局 + 响应式（含高 DPI 适配）
  app.js                交互：视图、阅读器、结果页、批量、工具箱、设置
  src/core.js           引擎：解包、诊断、清理、段落重建、压图、分卷、重建目录、ZIP 打包、只读预览
  vendor/fflate.js      只用于解包
  assets/icon.svg       应用图标（打开的书 + 压缩箭头）

desktop/                桌面版外壳（Electron）
  main.js               窗口、菜单、默认输出目录、IPC 写盘、下载兜底
  preload.js            只暴露一组有边界的能力（保存/选目录/开目录/检查更新）
  package.json

tools/
  build_standalone.py   把整个网页版内联成一个 HTML
  assemble_desktop.py   组装 Electron 运行时 + 我们的 app
  verify_epub.py        23 项结构校验（命令行可单跑）
  check_version.py      按指定版本核对包结构（2.0 / 3.0，独立于 JS 解析器）
  epub_spine.py         抽出 spine 顺序/标题/开头/目录，供分卷测试核对不丢不重不乱序
  make_*.py             各种样书生成器（含 120 张图的多图样书）

dist/
  epubfix-standalone.html     单文件网页版
  EPUBMaster-win32-x64/       桌面版（免安装）
  icon.ico                    6 帧多尺寸图标（16/32/48/64/128/256）
  使用说明.txt                给接收者的三分钟说明
```
